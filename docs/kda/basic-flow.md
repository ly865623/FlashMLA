# Kernel Design Agents 基础流程提示词

你正在任务实现工作区中工作。你的目标是为下述任务产出最优的正确实现。

## 任务约定

- 任务名称：`head64 prefill 性能优化加强版`
- 目标：`期望tensorcore利用率可以达到45%以上， 这个是说tensorcore的理论利用率而不是ncu报告采集的利用率，用kernel实测的tflops除以B200的峰值利用率得到`
- 正确性要求：`必须通过仓库已有的正确性测试case`
- 性能或质量目标：`基于当前代码修改`
- 工作负载：`采用现有benchmark测试负载`
- 评测协议：`采用现有benchmark测试负载，不改变参数设置`
- 目标设备（如适用）：`<选择一张空闲且兼容的 GPU；采集基线前记录其 UUID、型号和初始物理编号>`
- 允许的实现方式：`编程语言与原kernel实现保持一致`
- 验证命令：`参考仓库的正确性验证命令`
- 评测命令：`使用仓库中benchmark性能测试命令`
- 采用标准：`每轮候选优化，性能提升0.5%以上才能保留`
- 性能报告：`docs/kda/performance.md， 保留每一轮优化的性能提升，即使没有收益也保留，在文档开头总结已经收录的优化及性能提升情况`

## 工作流程

1. 阅读仓库结构、现有实现、测试和任务文档。
2. 确定基线行为和验证路径；对于 GPU 任务，选择整个实验期间使用的空闲设备。
3. 仅研究本任务需要的参考资料。
4. 将实现计划草案写入 `docs/draft.md`。
5. 编辑代码前，先将草案转为可执行计划。
6. 使用固定的评测协议验证并测量初始基线；GPU 任务还必须使用选定的 GPU。保留源码、构建产物、环境和原始测量数据。
7. 每次实现一个候选方案，并验证每个有实质改动的候选方案。
8. 使用固定协议评测每个有效候选方案；GPU 任务始终使用同一张 GPU。记录每轮迭代，包括失败、结论不明确、无收益和性能回退的情况。
9. 更新 Markdown 性能报告，逐工作负载及汇总对比初始基线和父版本/当前最佳版本，再记录是否采用该方案的决定。
10. 最终改动应保持在任务约定的范围内。

## 设备与测量规则

- 多次采样检查 GPU 利用率、显存占用和活动进程后，选择一张兼容的 GPU。记录选择时间和依据。
- 通过 UUID 将基线、验证、候选评测和性能剖析固定到该物理 GPU，例如 `CUDA_VISIBLE_DEVICES="GPU-<selected-uuid>"`。应用程序随后使用逻辑设备 `cuda:0`；仅靠设备编号无法稳定标识同一张卡。
- 固定 UUID 不等于独占 GPU。测量前及测量过程中检查是否有其他任务竞争，并串行执行该 GPU 上的所有本任务测量，包括其他智能体发起的测量。如果设备被占用，应等待并在同一张 GPU 上重试；不得静默换卡或终止其他用户的任务。
- 保留初始基线结果。将后续的基线/父版本对照重测与初始测量区分开来。交错运行对照版本和候选版本以检测漂移；将受干扰的运行标记为无效，并保留记录。
- 记录源码版本和补丁、构建/产物标识、准确命令、依赖/编译器/驱动版本，以及相关的设备频率、功耗和温度状态。如果设备或评测协议发生变化，应开启新的比较系列并重新测量基线。

## 性能报告要求

- Markdown 报告开头应汇总所有通过正确性验证且可复现的收益：优化点、迭代 ID、对比对象、受影响的工作负载、各工作负载及汇总收益、证据链接，以及该改动是否仍保留在当前最佳版本中。
- 即使候选方案因其他工作负载回退而被拒绝，也应记录仅在部分工作负载上得到验证的收益。明确标注局部收益、其他回退、汇总结果和拒绝状态。噪声范围内的变化或无效测量不属于已验证收益。
- 按时间顺序记录每轮迭代，包括假设/改动、父版本、正确性结果、设备 UUID、产物标识、各工作负载的耗时和波动、汇总结果、与初始基线及父版本/当前最佳版本的对比，以及保留/修改/拒绝的决定和原因。
- 清楚区分加速比和耗时降低比例。不得将不同实验的收益相加，也不得把单项收益描述为最终候选方案组合后的实测收益。
- 构建、正确性和测量失败也要记录，对比结果填 `N/A` 并注明原因。无效或受噪声影响的测量不能证明收益。CSV/JSONL 和原始日志可作为支撑材料，但不能替代 Markdown 报告。

## 计划草案要求

`docs/draft.md` 中的草案应包含：

- 当前基线及其验证方式。
- 选定的 GPU、固定工作负载和评测协议，以及 Markdown 报告路径。
- 主要风险和未知项。
- 按预期价值和风险排序的候选实现方向。
- 第一批具体实现步骤。
- 准确的验证与评测命令。
- 采用、修改或拒绝候选方案所需的证据。

草案完成前，不得开始实现。
